Transparent methodology, data handling, threat intelligence, asset classification, and scan freshness.

Asset Classification & Inventory Visibility

Asset groups are derived using transparent hostname rules plus explicit Rapid7 OS identification where defined. These tags are operational classifications, not authoritative CMDB data. Rapid7 OS values are preserved and are never replaced by hostname-derived OS guesses.

Rapid7 Scan Freshness

Current <3 days   Aging 3–10 days   Stale >10 days   Unknown no valid scan date.

Scan freshness is a data-confidence indicator only and does not change vulnerability or asset priority ranking.

Threat Intelligence

FIRST EPSS and CISA KEV are downloaded as public catalogs and matched locally to Rapid7 CVEs. Rapid7 finding data is not sent to either provider. Each source can update independently and last-known-good intelligence is retained when an update fails.

Direct or Proxy Connectivity

Threat-intelligence downloads can use direct HTTPS connectivity or a configured corporate proxy. Proxy configuration is stored separately from Rapid7 analysis data.

For TLS inspection, trust the approved corporate CA in the container rather than disabling certificate verification.

Data handling

Uploaded Rapid7 data is processed in the temporary analysis session. Public threat-intelligence catalogs and application configuration are the intentionally persistent datasets.
